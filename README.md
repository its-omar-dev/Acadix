## ما هي الأداة؟

تكتب مجالاً مثل «تحليل البيانات» أو «Python»، وتختار مستواك، فتحصل خلال ثوانٍ على:

1. **ملخص** عن أهمية المجال لمستواك.
2. **أربع مراحل** (تأسيس، توسع، احتراف، سوق العمل)، لكل مرحلة 3 إلى 5 مهام قابلة للتنفيذ.
3. **منارات للتعلّم:** روابط دورات وفيديوهات مرتبطة بالموضوع.

ثم تتابع تقدمك بتحديد المهام المنجزة، فتضيء نجوم السماء تدريجياً.

## كيف تستخدمها؟

1. **اكتب الموضوع** في مربع البحث، أو اضغط أحد الوسوم الجاهزة (Python، تطوير الويب، الذكاء الاصطناعي...).
2. **اختر المستوى:** مبتدئ، متوسط، أو متقدم.
3. اضغط **توليد**، وانتظر بضع ثوانٍ أثناء ظهور شاشة التحميل.
4. **حدّد المهام** التي أنجزتها: تُضيء النجمة وتتصل بالخط الذهبي، وتتحرك حلقة النسبة المئوية. وعند إكمال مرحلة كاملة يتوهج إطارها.
5. **احفظ أو شارك:**
   - زر **📷 حفظ كصورة** يصدّر الخارطة PNG.
   - زر **🔗 نسخ رابط المشاركة** يعطي رابطاً دائماً (متاح عند تفعيل قاعدة البيانات).
6. من قسم **مكتبتي** ترجع لأي خارطة سبق أن ولّدتها، وهي تُحفظ تلقائياً في متصفحك.

> تقدمك ومكتبتك محفوظان في متصفحك فقط (`localStorage`)، فمسح بيانات المتصفح يمحوهما.

## التشغيل محلياً خطوة بخطوة

### ما تحتاجه

- **Python 3.10 أو أحدث** ([تحميل](https://www.python.org/downloads/))، وعلى ويندوز فعّل خيار *Add Python to PATH* أثناء التثبيت.
- **Git** ([تحميل](https://git-scm.com/downloads)) أو حمّل المشروع كملف ZIP من GitHub.
- **مفتاح Groq مجاني** من [console.groq.com/keys](https://console.groq.com/keys).

### الخطوات

**1. حمّل المشروع**

```bash
git clone https://github.com/its-omar-dev/Acadix.git
cd Acadix
```

**2. أنشئ بيئة افتراضية** (يُنصح بها حتى لا تتعارض المكتبات)

ويندوز:
```powershell
python -m venv venv
venv\Scripts\activate
```

لينكس وماك:
```bash
python3 -m venv venv
source venv/bin/activate
```

**3. ثبّت المكتبات**

```bash
pip install -r requirements.txt
```

**4. ضع مفتاح Groq في متغير بيئة**

ويندوز PowerShell:
```powershell
$env:GROQ_API_KEY="ضع_مفتاحك_هنا"
```

ويندوز CMD:
```bat
set GROQ_API_KEY=ضع_مفتاحك_هنا
```

لينكس وماك:
```bash
export GROQ_API_KEY="ضع_مفتاحك_هنا"
```

> المتغير يعيش في نافذة الطرفية الحالية فقط. إن أغلقتها فأعد الأمر. ولا تكتب المفتاح داخل `app.py` ولا ترفعه إلى GitHub.

**5. شغّل الأداة**

```bash
python app.py
```

**6. افتح المتصفح** على العنوان الذي يظهر في الطرفية (غالباً `http://127.0.0.1:5000`).

لإيقاف الخادم اضغط `Ctrl + C`.

## الإعدادات الاختيارية

الأداة تعمل بمفتاح Groq وحده. هذه المتغيرات تضيف ميزات:

| المتغير | الوظيفة |
|---|---|
| `GROQ_API_KEY` | **مطلوب.** مفتاح Groq |
| `DATABASE_URL` | رابط قاعدة Postgres (مثل [Neon](https://neon.tech) المجانية). يفعّل الكاش الدائم وروابط المشاركة والإحصاءات |
| `ADMIN_TOKEN` | رمز سري لصفحة الإحصاءات؛ الأفضل إرساله في ترويسة `Authorization: Bearer ...`، مع دعم رابط `?token=` للتوافق |
| `SECRET_KEY` | مفتاح جلسات Flask ثابت وعشوائي (مطلوب في النشر متعدد العمال) |
| `COOKIE_SECURE` | اضبطه إلى `1` لفرض إرسال Cookie عبر HTTPS فقط في الإنتاج |

لتوليد رمز قوي:

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

عند ضبط `DATABASE_URL` يُنشأ جدول `roadmaps` تلقائياً عند أول تشغيل. يدعم PostgreSQL (بما فيه Neon) وSQLite للاختبارات. وبدونه تعمل الأداة كاملة عدا المشاركة والكاش الدائم والإحصاءات.

**إعداد أمني للإنتاج:** أنشئ `SECRET_KEY` و`ADMIN_TOKEN` بقيمتين عشوائيتين منفصلتين، ولا تضعهما في Git أو README. اضبط `COOKIE_SECURE=1` عند استخدام HTTPS. لا تستخدم مفتاحاً افتراضياً أو مشتركاً بين البيئات.

## توليد خرائط جاهزة

للمواضيع الشائعة يمكنك توليد الخرائط مرة واحدة وحفظها في `popular.json`، فتُخدَم فوراً بلا استهلاك من حصة Groq:

```powershell
$env:GROQ_API_KEY="ضع_مفتاحك_هنا"
python make_popular.py
```

- يولّد 33 خريطة (11 موضوعاً × 3 مستويات) ويستغرق نحو 15 دقيقة لاحترام حدود Groq.
- آمن لإعادة التشغيل: يتخطى ما تم توليده، ويحفظ بعد كل خريطة.
- يجب أن يكون `popular.json` بجانب `app.py`.

## النشر على الإنترنت

### الخيار الأول: Fly.io (Docker)

المشروع يحتوي على `fly.toml` جاهز وDockerfile. الإعداد الحالي يستخدم منطقة `fra`، والمنفذ الداخلي `8000`، وفحص صحة على `/health`، مع إبقاء آلة واحدة تعمل لتجنب تأخر أول طلب.

**1. ثبّت flyctl وسجّل الدخول**

راجع [دليل تثبيت flyctl](https://fly.io/docs/flyctl/install/) ثم نفّذ:

```bash
fly auth login
```

**2. أنشئ التطبيق مرة واحدة**

اسم التطبيق الحالي في `fly.toml` هو `acadix`. إذا كان التطبيق موجوداً في حسابك، تخطَّ خطوة الإنشاء. وإذا كان الاسم محجوزاً لتطبيق آخر، أنشئ اسماً متاحاً وعدّل قيمة `app` في `fly.toml` لتطابقه:

```bash
fly apps create acadix
```

**3. أضف الأسرار**

أنشئ `SECRET_KEY` و`ADMIN_TOKEN` بقيم عشوائية، ولا تضعها في الملفات أو GitHub:

```bash
fly secrets set GROQ_API_KEY="مفتاح_Groq"
fly secrets set SECRET_KEY="قيمة_عشوائية_طويلة"
fly secrets set ADMIN_TOKEN="رمز_إدارة_عشوائي"
```

إذا أردت روابط المشاركة والكاش الدائم والإحصاءات، أضف `DATABASE_URL` من مزود PostgreSQL:

```bash
fly secrets set DATABASE_URL="postgresql://..."
```

بدون قاعدة بيانات، يبقى التوليد متاحاً لكن المشاركة والكاش الدائم والإحصاءات لا تعمل.

**4. انشر وتحقق**

```bash
fly deploy
fly status
fly logs
```

بعد النشر، تحقق من `https://اسم-التطبيق.fly.dev/health`. لا تعتبر الإعداد المحلي أو نجاح بناء Docker دليلاً على نشر حي؛ يلزم تنفيذ `fly deploy` بحسابك وأسرارك.

**ملاحظات التكلفة:** الإعداد الحالي يترك آلة واحدة قيد التشغيل دائماً (`min_machines_running = 1`) لتقليل زمن الاستجابة. هذا قد يترتب عليه استهلاك/تكلفة حسب خطة Fly.io؛ راجع [الأسعار](https://fly.io/docs/about/pricing/) قبل النشر. يمكنك تغيير إعدادات التشغيل التلقائي في `fly.toml` إذا كانت الأولوية لتقليل التكلفة بدلاً من الاستجابة الفورية.

### الخيار الثاني: VPS باستخدام Docker

بعد تثبيت Docker على الخادم ونسخ المستودع:

```bash
docker build -t acadix .
docker run -d --name acadix --restart unless-stopped \
  -p 8000:8000 \
  -e GROQ_API_KEY="مفتاح_Groq" \
  -e SECRET_KEY="قيمة_عشوائية_طويلة" \
  -e ADMIN_TOKEN="رمز_إدارة_عشوائي" \
  -e COOKIE_SECURE=1 \
  acadix
```

إذا استخدمت PostgreSQL، أضف `-e DATABASE_URL="postgresql://..."`. استخدم Reverse Proxy مثل Caddy أو Nginx لتوفير HTTPS، ولا تعرض منفذ التطبيق مباشرة دون TLS في الإنتاج.

### الخيار الثالث: Render

يمكنك ربط المستودع بخدمة Web Service على [Render](https://render.com):

- **Build Command:** `pip install -r requirements.txt`
- **Start Command:** `gunicorn --bind 0.0.0.0:$PORT --workers 1 --threads 8 --timeout 60 app:app`
- أضف `GROQ_API_KEY` و`SECRET_KEY` و`ADMIN_TOKEN` من Environment.
- أضف `DATABASE_URL` إذا أردت المشاركة والكاش الدائم والإحصاءات.
- استخدم `/health` كمسار فحص الصحة.

تختلف حدود النوم والتكلفة حسب خطة Render الحالية؛ راجع صفحة الأسعار والقيود قبل الاعتماد على الخدمة المجانية.

## الميزات

**للمستخدم**
- خارطة مخصصة لأي موضوع ومستوى، بأربع مراحل ومهام واضحة.
- **بث تدريجي (SSE):** تظهر كل مرحلة وكوكبتها فور وصولها، مع رجوع تلقائي إلى التوليد التقليدي إذا تعذّر البث أو لم تكتمل المراحل.
- سماء تفاعلية: نجوم تُضاء، وخطوط تُرسم، وحلقة تقدّم، وأسماء نجوم عربية للكوكبات.
- مكتبة محلية تحفظ خرائطك وتقدمك.
- حفظ كصورة، وروابط مشاركة دائمة.
- واجهة عربية RTL متجاوبة (حاسوب وجوال)، تدعم لوحة المفاتيح وتفضيل تقليل الحركة.

**للمطوّر**
- **توليد متوافق:** يحافظ الخادم على صيغة Markdown الحالية التي تفهمها الواجهة، مع أداة تحقق مستقلة للبنية المنظمة لا تغيّر مسار التوليد.
- **سلسلة موديلات احتياطية** على Groq: `gpt-oss-120b` ← `gpt-oss-20b` ← `llama-3.3-70b` ← `llama-3.1-8b`. عند نفاد حصة موديل ينتقل الكود للتالي تلقائياً.
- **ثلاث طبقات كاش:** `popular.json`، ثم ذاكرة الخادم، ثم Postgres.
- **حد طلبات:** 6 خرائط جديدة في الساعة لكل IP (المخزنة لا تُحتسب).
- **الأمان:** لا يُحقن HTML من الذكاء الاصطناعي، والروابط الخارجية تُتحقق، والمدخلات محددة الطول.

| المسار | الوظيفة |
|---|---|
| `/` | الصفحة الرئيسية والتوليد التقليدي المتوافق مع العملاء السابقين |
| `/generate/stream` (POST) | بث مراحل الخارطة تدريجياً عبر Server-Sent Events (SSE) |
| `/share` (POST) | إنشاء رابط مشاركة؛ يتطلب جلسة وCSRF token وPostgreSQL |
| `/r/<id>` | عرض خريطة مشاركة عامة بمعرّف عشوائي |
| `/health` | فحص التطبيق واتصال Postgres عند ضبطه |
| `/stats` | أكثر المواضيع طلباً (يتطلب `ADMIN_TOKEN`) |

## الأمان وحماية البيانات

تطبق Phase 2 طبقات حماية أساسية:

- أسرار Groq وPostgres وADMIN_TOKEN وSECRET_KEY تُقرأ من متغيرات البيئة، ولا تُخزّن في المستودع.
- إنشاء المشاركة محمي برمز CSRF مرتبط بجلسة المتصفح، مع رفض الطلبات غير JSON والتحقق من الحقول والأحجام وروابط HTTP(S).
- معرّفات المشاركة عشوائية وغير متسلسلة، ولا يمكن الوصول إلى سجلات الكاش الداخلية عبر مسار المشاركة.
- استعلامات قاعدة البيانات تستخدم SQLAlchemy parameters بدلاً من تركيب SQL من مدخلات المستخدم.
- `/stats` مخفي عند عدم إعداد ADMIN_TOKEN، ويقارن الرمز بمقارنة ثابتة الزمن؛ استخدم `Authorization: Bearer ...` لأن وضع الرمز في query string قد يعرّضه لسجلات الوصول وسجل المتصفح.
- ترويسات أمنية تشمل CSP و`X-Content-Type-Options` و`X-Frame-Options` وReferrer Policy، مع HSTS عند HTTPS.
- جلسات المتصفح تستخدم HttpOnly وSameSite=Lax؛ فعّل `COOKIE_SECURE=1` في الإنتاج.

هذه حماية تطبيقية متعددة الطبقات وليست ضماناً مطلقاً: لا يوجد حتى الآن تسجيل دخول للمستخدمين، كما أن محدد الطلبات الحالي داخل ذاكرة العملية وليس موزعاً بين عدة خوادم. ستُعالج تحسينات النشر والمراقبة وحدود الطلبات في المراحل اللاحقة.

## حل المشاكل الشائعة

| المشكلة | الحل |
|---|---|
| `ModuleNotFoundError` | شغّل `pip install -r requirements.txt` داخل البيئة الافتراضية المفعّلة |
| تظهر رسالة «تعذّر توليد الخارطة» | تأكد من ضبط `GROQ_API_KEY` في **نفس نافذة الطرفية** التي شغّلت منها الأداة، وراجع الرسائل المطبوعة فيها |
| «الخدمة مشغولة» | نفدت الحصة المجانية لكل الموديلات مؤقتاً؛ جرّب بعد دقائق |
| «وصلت إلى حد الخرائط الجديدة» | حد الطلبات لكل IP (6/ساعة). جرّب موضوعاً من الوسوم الجاهزة أو عد لاحقاً |
| خطأ `proxies` من مكتبة يوتيوب | لازم `httpx==0.27.2`، وهو مثبت في `requirements.txt` فأعد التثبيت |
| `ImportError` عند تشغيل `make_popular.py` | تأكد أن `app.py` في المجلد نفسه وأنه آخر نسخة من المستودع |
| `Address already in use` | منفذ 5000 مشغول؛ أغلق البرنامج الآخر أو أعد تشغيل الطرفية |
| الأمر لا يعمل على ويندوز | `export` للينكس فقط؛ استخدم `$env:` في PowerShell أو `set` في CMD |
| مشاركة لا تظهر | زر المشاركة يحتاج `DATABASE_URL`؛ راجع سجل الطرفية عن سطر يبدأ بـ `DB:` |
